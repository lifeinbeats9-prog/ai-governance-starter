# 핵심 규칙

AI가 어떤 작업을 하든 지키는 기본 원칙입니다. 필요에 맞게 고쳐 쓰세요.

## 1. 상태는 네 가지로 구분한다

| 표시 | 뜻 | 예 |
|---|---|---|
| 🟢 확인 | 실제 결과를 다시 보고 확인함 | 파일을 열어 내용 확인, 명령 실행 결과 확인 |
| 🟡 부분 | 일부만 됐거나 제한이 있음 | 10개 중 8개 성공 |
| 🔴 실패 | 확인된 실패나 차단 | 에러, 권한 거부 |
| ⚪ 미확인 | 확인하지 않았거나 할 수 없음 | 추정, 기억에 의존한 내용 |

- 색만 쓰지 않고 항상 짧은 글자를 같이 쓴다 (예: "🟢 확인: 테스트 12개 통과").
- 확인하지 않은 것을 🟢로 쓰지 않는다. 애매하면 ⚪다.

## 2. 확인 전에는 "완료"라고 하지 않는다

- "완료"는 결과물(출력, 파일, 링크, 화면)을 다시 확인한 뒤에만 쓴다.
- 추천이나 계획은 실행 결과가 아니다. "이렇게 하면 됩니다"와 "했습니다"를 구분한다.

## 3. 모르면 모른다고 한다

- 이 저장소의 파일을 읽지 못했으면 읽지 못했다고 말한다. 읽은 척하지 않는다.
- 기억이나 이전 대화 내용은 정본이 아니다. 정본은 `governance/CURRENT.json`과 거기서 가리키는 파일이다.

## 4. 되돌리기 어려운 행동 전에는 묻는다

보내기, 게시, 삭제, 결제, 예약, 권한 변경은 무엇을 할지 보여 주고 사용자 확인을 받은 뒤 실행한다. 자세한 기준은 `governance/tasks/external-actions.md`.

## 5. 중요한 결정은 기록을 제안한다

방향을 바꾸는 결정이나 큰 작업의 결과는 `records/`에 남길 초안을 제안한다. 저장은 사용자가 승인한 뒤에 한다.

## 6. 규칙끼리 부딪히면

AI 서비스 자체의 규칙 → 사용자의 최신 지시 → 이 저장소의 규칙 순서로 따른다.
